# 安装与使用

## 首次运行

1. 解压完整项目，保持 `backend/`、`frontend/` 和 `examples/` 与 `run.py` 同级。
2. 安装 Python 3.11–3.13，并确认 `python --version` 正常。
3. 在项目根目录运行：

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe run.py
   ```

4. 浏览器打开 `http://127.0.0.1:8000`。不要直接双击 `frontend/app.html`。
5. 点击「用合成示例试一试」，确认四区域位移接近 5 px。

虚拟环境应在目标电脑重新创建，无需复制其他电脑的环境。macOS / Linux 使用 `.venv/bin/python` 替换上述 Windows 路径。

## 两张图像分析

选择引擎，再选择参考图像与目标图像。两图需来自同一固定视角，且像素尺寸一致、裁剪范围一致。支持单帧 JPEG / PNG / BMP / TIFF，每张最多 12 MiB、1200 万像素，宽高均至少 64 px。图片方向按文件编码的像素阵列读取，不应用 EXIF 旋转；请预先将两图转成方向一致的普通图片。

匹配不足的区域显示 `—`，不能解释为没有位移。有效区域的位移按原图坐标计算，匹配展示图缩放不会改变数值。

## 时间序列分析

先选基础图像并填写拍摄日期，再添加对比图像，逐张填入日期。日期应晚于基础图像，且不能重复；系统会将图像与日期一起排序。

可以上传 1–20 张图像；每个区域至少有三个有效对比日期才进行趋势回归。基础图像不作为人为补入的零位移点。默认趋势阈值为 0.5 px/天，可通过 API 的 `slope_threshold` 参数修改。页面总览显示最后一个对比日期，所有日期的数值列在明细表里。

## 报告与本地数据

JSON 包含完整区域与趋势结果；CSV 每行包含一个日期、一个区域的像素统计。报告和匹配图默认保存在 `var/<task_id>/`。历史接口只读取真实完成的本地报告，重启服务后仍可读取；界面尚未提供历史列表。

服务不保留原始上传文件；匹配图仍包含输入场景，报告目录应作为实验数据管理。确认不需要后，可自行清理对应任务目录。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 研究模型待配置 | 先用 SIFT 验证环境，或参阅 `models.md` 接入已有研究目录 |
| 模型已配置但推理失败 | 检查 PyTorch 版本、原训练版源码与权重是否匹配；错误详情在本机服务日志 |
| 图像尺寸不一致 | 统一图像分辨率和裁剪区域；服务不会静默缩放测量图像 |
| 部分区域为 `—` | 换用纹理清晰、视角一致的图像，不要将缺失值当作 0 |
| 日期不足 | 补充至少三个有效对比拍摄日期 |
| 端口被占用 | 使用 `python run.py --port 8080` |

## 运行边界

默认是本机单任务研究服务，没有登录、访问隔离或后台任务队列。若将来部署公网，需要另做访问控制、请求体总量限制、任务隔离、存储清理与 HTTPS 配置。GitHub 上的源码展示不依赖将分析服务开放公网。
